# Claude Code 지시 프롬프트: 점수 구간별 결과 화면 + 타이틀 배경

아래 "프롬프트" 부분을 통째로 Claude Code에 붙여 넣는다.

---

## 프롬프트

프로젝트(~/mime-game, Godot 4.7 mono + C#)의 결과 화면과 타이틀 화면을 새 그림으로 바꾼다. 작업은 두 가지다.

### 0. 먼저 읽을 것 (수정 전에 읽고 현재 구조를 3~5줄로 요약한 뒤 시작)
- `scripts/Hud.cs`: 지금의 결과 오버레이(점수, 배율, 광석별 개수, 서버 순위, 상위 10명, 남은 횟수)가 어떻게 만들어지는지
- `scripts/Title.cs`, `scenes/Title.tscn`: 타이틀 배경과 메뉴(게임 시작, 랭킹 보기, 게임 설명), 입력 화면, 랭킹 패널
- `data/GameData.cs`: 상수는 여기에 둔다(이 프로젝트의 규칙)
- `assets/sprites/README.txt`: 에셋 규칙(전부 4배 확대 도트, 텍스처 필터 Nearest, 화면에서 0.25배)
- `docs/ui/result_layout_ref_tier1~4.png`, `docs/ui/title_ref.png`: 사용자가 만든 레이아웃 목업(1920×1080 = 480×270 화면의 4배)

### 1. 결과 화면: 최종 점수 구간별 그림 4종

에셋(이미 들어 있음, 수정 금지): `assets/sprites/ui/result/result_tier1.png ~ result_tier4.png` (각 856×712, 화면에서 0.25배 = 214×178)

**구간 규칙** (이번 판의 최종 점수 기준. 최고점이 아니다)
| tier | 점수 | 파일 | 문구 |
| --- | --- | --- | --- |
| 1 | 0 ~ 24,999 | result_tier1.png | 당신은 돌 몇개 밖에 건지지 못했습니다... |
| 2 | 25,000 ~ 49,999 | result_tier2.png | 당신은 돈을 꽤 벌었습니다. 수고했어요! |
| 3 | 50,000 ~ 74,999 | result_tier3.png | 당신은 황금도토리의 주인이 되었습니다! |
| 4 | 75,000 이상 | result_tier4.png | 당신은 세계의 부호가 되었습니다! |

- 구간 계산은 정수 나눗셈 한 줄로 끝낸다(점수 ÷ 25,000, 최대 3으로 제한 → 0~3을 tier 1~4로). 경계값 25,000은 tier 2, 24,999는 tier 1이다.
- 구간 크기(25,000), 구간 수(4), 문구 4개, 파일 경로 규칙은 `GameData.cs` 상수로 둔다. 숫자를 다른 파일에 직접 쓰지 않는다(밸런스를 나중에 바꿀 수 있게).

**화면 구성** (480×270 화면 기준, 목업과 같게)
- 왼쪽 절반(x 0~240): 검은 배경. 여기에 **상세 점수와 랭킹**을 표시한다. 지금 결과 오버레이가 보여 주는 항목을 하나도 빼지 않고 옮긴다: 최종 점수와 배율, 달성한 조합 이름(`GameData.ComboName` 사용 가능), 광석 5종 개수, 내 순위/전체 참가자 수, 남은 판 수, 상위 10명 순위표. 240×270 안에 겹치지 않고 들어가야 한다(광석 5종은 한 줄 요약 등으로 줄여도 된다).
- 오른쪽 절반(x 240~480): 흰 배경. 위쪽 중앙(x 중심 360, y 약 30~42)에 해당 tier 문구, 그 아래 (253, 46) 위치에 그림(TextureRect, 0.25배, 크기 214×178).
- 폰트는 기존에 쓰는 Galmuri11을 그대로 쓴다. 텍스처 필터는 Nearest, 늘어나거나 흐려지면 안 된다.
- 지금처럼 UI는 코드로 만든다(씬 파일에 노드를 새로 만들지 않는다).

**동작**
- 서버 제출·순위 조회 흐름(ApiClient, Session, RoundSystem)은 바꾸지 않는다. 결과 화면이 뜨는 시점과 순서도 그대로다.
- 서버 제출이 실패한 경우에도 tier 그림과 문구, 왼쪽의 점수·광석 정보는 보여 준다(그림은 로컬 점수로 정해진다). 순위 칸만 기존 실패 처리(재전송 버튼 등)를 그대로 쓴다.
- 그림 파일을 못 읽으면 게임이 멈추지 않게 하고 Output에 한 줄 경고만 남긴다.

### 2. 타이틀 화면: 배경 교체

에셋(이미 들어 있음, 수정 금지): `assets/sprites/ui/title/title_screen.png` (1920×1080, 로고 "Ready / Ore, nut"가 그림에 이미 그려져 있다)
- 타이틀 배경을 이 그림 전체 화면으로 바꾼다(0.25배, Nearest). 로고는 그림 안에 있으니 **로고 글자를 코드로 다시 쓰지 않는다**.
- 로고는 480×270 화면 기준 x 95~200, y 50~95 부근에 있다. 메뉴 버튼, 입력 화면, 랭킹·설명 패널이 이 영역을 가리지 않게 위치를 조정한다.
- 기존 메뉴 동작(게임 시작, 랭킹 보기, 게임 설명, 서버 확인, 입력 화면)은 그대로 둔다. 바꾸는 건 배경과 그에 따른 배치뿐이다.

### 3. 지킬 규칙
- 코드 주석은 파일 맨 위 설명 한 줄만 쓰고 나머지 주석은 쓰지 않는다.
- 점수 계산, 서버 검증값(`OreValue`, `Combos` 등), `ApiClient`는 건드리지 않는다.
- `.import` 파일은 직접 고치지 않는다(Godot이 만든다). 새 `.cs` 파일을 만들면 `.uid`는 Godot이 만들게 두고 Build만 한다.
- 커밋은 하지 않는다.

### 4. 확인과 보고
- 아래 점수로 tier가 맞게 나오는지 확인한다: 0, 24,999, 25,000, 49,999, 50,000, 74,999, 75,000, 98,175(실제 판에서 나온 값). 확인용으로 점수를 임시로 고정했다면 반드시 되돌리고, 되돌렸다고 보고에 적는다.
- Build 오류 0개를 확인한다. 실행 확인이 불가능한 항목(예: Windows에서의 폰트)은 "확인 못 함"이라고 적는다.
- 마지막에 보고: ① 바꾼 파일 목록 ② **씬/노드 작업**(없으면 "없음") ③ 확인한 것과 확인 못 한 것 ④ 내가 따로 판단해서 정한 부분.
- 지침이 서로 안 맞거나 모호한 부분은 추측해서 진행하지 말고 한 번에 하나씩 물어본다.
